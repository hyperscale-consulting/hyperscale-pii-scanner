# hyperscale-pii-scanner design

Date: 2026-10-12
Status: approved for planning

## Purpose

Hyperscale builds Django apps from App Studio designs. Several accept documents
about people (expert witness reports, case notes, clinical material) that are
supposed to have been anonymised before upload, then pass the content to an
LLM. This library is the platform's second line of defence: a deterministic,
in-process scan that finds residual personal identifiers in English text so the
app can hold the upload until a person has replaced or confirmed each hit.

App Studio advertises it in the platform guide as the service behind the
sentence "System scans the document for residual identifiers", so it is one
implementation with a stable contract and measured behaviour.

## Hard constraints

- No network calls at runtime. No LLM. CPU only, inside the calling process.
- Deterministic: the same input and configuration give the same hits, for the
  same library versions on the same CPU architecture.
- Best effort by design. The library never claims text is anonymised; it
  reports what it found. The README and platform guide say this plainly.
- English only (`language="en"`); any other language raises `ValueError`.

## Decisions taken during design

| Decision | Choice | Why |
|---|---|---|
| Engine | Presidio analyzer 2.2.364 with spaCy 3.8.16 | Required by the brief; both have Python 3.14 wheels |
| Model | `en_core_web_md` 3.8.0 vendored into the wheel | Not on PyPI, and PyPI rejects direct-URL dependencies. MIT licence permits redistribution. Wheel stays around 35 MB, under PyPI's 100 MB cap |
| Large model | Switchable through `configure(model=...)` | 400 MB wheel cannot be vendored; callers install it themselves |
| Import name | `hyperscale.pii_scanner` (namespace package) | Matches hyperscale-crypto and hyperscale-trust |
| Python | 3.14 only | Matches sibling libraries; spaCy requires <3.15 |
| Licence | MIT | Matches sibling libraries; compatible with every dependency |
| Gazetteer | GeoNames GB, CC BY 4.0 | Population field allows a threshold that excludes hamlets named like common words |
| Redaction | Own implementation, no presidio-anonymizer | Anonymizer operators are per entity type and cannot call a per-hit callable |
| Registry | Built explicitly in code | A Presidio upgrade cannot re-enable US recognisers |
| Recogniser reuse | Presidio's NHS, NINO, phone, email, URL recognisers reused | NHS already has the modulus 11 check; duplicating it adds nothing |

```
    gazetteer.py       LOCATION from the place-name list
  _gazetteer.py        loads data/uk_places.txt into a matcher
  _postprocess.py      kind mapping, overlap resolution, suppression
  _redact.py           redact()
  documents.py         extract_text() (optional extra)
  data/uk_places.txt   gazetteer (committed, generated by a script)
  _model/              vendored spaCy model (git-ignored, fetched by script)
scripts/
  vendor_model.py      download the pinned model wheel, verify sha256, unpack
  build_gazetteer.py   download GeoNames GB, filter, write data/uk_places.txt
  gazetteer_stoplist.txt  hand-maintained names to exclude
  gazetteer_extra.txt     hand-maintained names to include

  fixtures/corpus/     *.txt documents with *.expected.json sidecars
```

Build backend is `uv_build` with `module-name = "hyperscale.pii_scanner"`. The
wheel includes `data/` and `_model/`. The sdist includes the same so a source
install also works offline.

## Public interface

```python
from hyperscale.pii_scanner import (
    Hit, HitKind, ScannerVersion, configure, redact, scan, scanner_version, __version__,
)

hits: list[Hit] = scan(
    text,
    allowlist=["Dr Ian Brown", "IDB Experts Ltd"],
    placeholder_patterns=[r"\b[A-Z]{3,}\d[A-Z]{1,3}\b", r"\([A-Z][A-Z ]+\d?\)"],
    language="en",
)

redacted = redact(text, hits, token_for=lambda hit: f"[{hit.kind.value.upper()}]")

scanner_version()  # ScannerVersion(library=..., presidio_analyzer=..., spacy=..., model_name=..., model_version=...)
configure(model="en_core_web_lg")  # before the first scan only
```

### Types

`HitKind` is a closed `enum.StrEnum` with exactly these members and values:
`person`, `location`, `organisation`, `date`, `date_of_birth`, `age`,
`postcode`, `nhs_number`, `national_insurance_number`, `phone`, `email`,
`url`, `case_reference`. Enum order is the tie-break order for overlaps.

`Hit` is a frozen dataclass with `slots=True`: `kind: HitKind`, `text: str`,
`start: int`, `end: int`, `score: float`, `recogniser: str`. `text` is always
`source[start:end]`. `recogniser` is the Presidio recogniser name that produced
the hit (for example `NhsRecognizer`, `SpacyRecognizer`, `UkDateRecognizer`).

`ScannerVersion` is a frozen dataclass: `library`, `presidio_analyzer`,
`spacy`, `model_name`, `model_version`, all strings, with `__str__` giving a
single line suitable for audit logs, for example
`hyperscale-pii-scanner 0.1.0; presidio-analyzer 2.2.364; spacy 3.8.16; en_core_web_md 3.8.0`.

### Functions

`scan(text, *, allowlist=(), placeholder_patterns=(), language="en") -> list[Hit]`

- `text` is a `str`. Empty text returns an empty list without loading the model.
- `allowlist` is an iterable of strings. `placeholder_patterns` is an iterable
  of regular expression strings compiled with the `re` module; an invalid
  pattern raises `ValueError` before any scanning.
- Returns hits sorted by `start` then `end`, non-overlapping, each with
  `score >= 0.3`.
- Thread-safe. Calls serialise on an internal lock.

`redact(text, hits, token_for=None) -> str`

- Default token is `[KIND]` using the upper-cased enum value.
- Raises `ValueError` if any hit's `text` does not equal `text[start:end]`,
  which catches hits from a different document.
- Overlapping hits in the input are resolved by keeping the earliest start,
  then the longest.

`scanner_version() -> ScannerVersion`. Does not load the model.

`configure(model: str | os.PathLike[str]) -> None`

- The only configuration point. Accepts a spaCy package name or a path to a
  model directory. Raises `RuntimeError` if the engine has already been built.
- Default is the vendored `en_core_web_md` directory inside the package.

`__version__` is read from package metadata.

### Documents extra

Installed with `hyperscale-pii-scanner[documents]`, which adds `python-docx`,
`openpyxl` and `defusedxml`. Importing `hyperscale.pii_scanner.documents`
without the extra raises `ImportError` with an install hint. The core package
never imports it.

```python
from hyperscale.pii_scanner.documents import extract_text, ExtractedText, Segment

doc = extract_text(path_or_bytes, kind="docx")   # kind is "docx" or "xlsx"
doc.text              # plain text, segments joined by "\n"
doc.segments          # list[Segment(start, end, label)]
doc.locate(hit.start) # "paragraph 14" | "table 2, row 3, cell 1" | "header 1" | "sheet Results, cell B20"
```

- Word: body paragraphs and tables in document order, then each section's
  header and footer paragraphs. Footnotes, comments and text boxes are not
  read, and the README says so.
- Excel: every non-empty cell, sheet by sheet in workbook order, row-major,
  using cached values rather than formulas. Each cell is its own segment.
- Untrusted input: the source is rejected with `ValueError` if larger than
  50 MB, if it is not a zip file, or if the sum of the declared uncompressed
  sizes of its members exceeds 250 MB. python-docx's parser has entity resolution disabled; openpyxl parses with
  an entity-safe lxml parser and uses defusedxml for streaming parses when it
  is installed, and the extra installs it. Parsing errors from the underlying libraries are wrapped
  in `ValueError`.

## Engine

`_engine.py` holds one `AnalyzerEngine` per process, built lazily on the first
non-empty scan under a construction lock (double-checked). The NLP engine is
Presidio's `SpacyNlpEngine` given the model path; Presidio skips its download
hook when the path exists. A second lock serialises `analyze` calls because
spaCy pipelines are not guaranteed thread-safe. The engine's
`supported_languages` is `["en"]` and the default score threshold is 0.3.

Memory: the loaded engine measured about 400 MB resident on macOS arm64 with
the medium model, rising to about 760 MB while analysing a 16,800-word
document. The README records the numbers from the measurement script.

## Recognisers

The registry is built in code from this list and nothing else:

| Presidio entity | HitKind | Recogniser | Origin |
|---|---|---|---|
| PERSON | person | SpacyRecognizer | spaCy NER |
| LOCATION (GPE, LOC, FAC) | location | SpacyRecognizer | spaCy NER |
| LOCATION | location | UkGazetteerRecognizer | ours |
| ORGANIZATION | organisation | SpacyRecognizer | spaCy NER |
| UK_DATE | date | UkDateRecognizer | ours |
| DATE_OF_BIRTH | date_of_birth | DateOfBirthRecognizer | ours |
| AGE | age | AgeRecognizer | ours |
| UK_POSTCODE | postcode | UkPostcodeRecognizer | ours, replaces Presidio's |
| UK_NHS | nhs_number | NhsRecognizer | Presidio |
| UK_NINO | national_insurance_number | UkNinoRecognizer | Presidio |
| PHONE_NUMBER | phone | PhoneRecognizer, regions ("GB",) | Presidio |
| EMAIL_ADDRESS | email | OfflineEmailRecognizer | Presidio subclass |
| URL | url | UrlRecognizer | Presidio |
| CASE_REFERENCE | case_reference | CaseReferenceRecognizer | ours |

Not registered, and listed in the README as not detected: spaCy DATE and TIME
(they include durations such as "three weeks"), NRP, credit cards, IBAN, IP
and MAC addresses, crypto wallets, medical licences, US identifiers, UK
passports, driving licences and vehicle registrations.

### UkDateRecognizer

Patterns, each anchored on word boundaries, with an optional leading weekday
name and comma:

- Textual day-month-year: `13 July 2026`, `13th July 2026`, `13th of July
  2026`, `3rd June, 2026`, `13 Jul 2026`, `13 Sept 2026`. Score 0.85.
- Month-day-year: `July 13, 2026`, `July 13th 2026`. Score 0.85.
- Month-year: `July 2026`, `Jul 2026`. Score 0.6.
- Numeric: `13/07/2026`, `13/7/26`, `13.07.2026`, `13-07-2026`, `2026-07-13`.
  Day 1 to 31, month 1 to 12, year two or four digits. Score 0.6.

A bare year is not a date. Month names are matched case-insensitively.

### DateOfBirthRecognizer

Runs the same date patterns, then keeps only matches preceded within 25
characters by one of: `DOB`, `D.O.B`, `date of birth`, `birth date`, `born`
(optionally followed by `on` or `in`). Score 0.9. The hit span is the date
only, so redaction leaves the label in place. Overlap resolution gives this
kind priority over `date`.

### AgeRecognizer

- `aged 34`, `aged 34 years`, `age 34`, `age: 34`
- `34 years old`, `34 year old`, `34-year-old`, `34 yrs old`, `34 yr old`
- `18 months old`, `aged 18 months`, `18-month-old`
- Number words from `one` to `twenty` and tens to `ninety` in the same
  positions, and hyphenated forms such as `six-year-old`.

Numbers above 120 are not ages. The hit span is the whole phrase. Score 0.7.

### UkPostcodeRecognizer

- Full form with the same position rules as Presidio's recogniser, space
  optional: score 0.6, and 0.45 when there is no space. `GIR 0AA` included.
- Outward code only (`SW1A`, `LS1`, `B33`) as a standalone token: score 0.05,
  with context words `postcode`, `post code`, `postal`, `area`, `district`.
  Presidio's context enhancer lifts a matched hit to 0.4, so outward codes are
  reported only when such a word appears within five tokens before them.

### CaseReferenceRecognizer

- Family, county and civil court case numbers: two letters, two digits, one
  letter, five digits (`ZC24C50123`, `FD24P00123`). Score 0.7.
- Neutral citations: `[2026] EWFC 12`, `[2024] EWHC 123 (Fam)`,
  `[2023] EWCA Civ 45`, `[2022] UKSC 1`, `[2026] EWFC 12 (B)`, also
  UKUT, UKFTT, EWCOP, EWCC, UKPC. Score 0.85.
- Crown Court numbers `T20247123` (T, S or U followed by eight digits) and
  CPS URNs (two digits, two letters, five to seven digits): score 0.2 with
  context words `case`, `URN`, `reference`, `ref`, `number`, so reported only
  with context.

### UkGazetteerRecognizer

Loads `data/uk_places.txt` once (one name per line, sorted, UTF-8). Matches
whole words, case-sensitive, longest first, including multi-word names such
as `Newcastle upon Tyne` and `Tower Hamlets`. Score 0.9, above spaCy's 0.85,
so an exact gazetteer match beats a same-span PERSON or ORGANIZATION label from
the model (which labels unfamiliar towns inconsistently) while a longer model
span still wins by length. Recogniser name `UkGazetteerRecognizer`. Implementation indexes names by their first word,
scans the text for capitalised tokens, and checks the candidate names
(longest first) at each token, so the cost is linear in the text length.

The build script:

1. Downloads `GB.zip` from GeoNames and reads `GB.txt`.
2. Keeps feature class `P` entries with population of at least 1,000, all
   `ADM2` entries (counties and unitary authorities) and the `ADM3` entries
   inside Greater London (admin2 code `GLA`, the London boroughs). Strips the
   prefixes `London Borough of`, `Royal Borough of`, `Metropolitan Borough
   of`, `City and Borough of`, `Borough of`, `City of`, `County of`,
   `District of` and `Sir`, and the suffixes `District`, `Borough` and
   `County Borough`, keeping only the stripped name (`Hackney`, not `London
   Borough of Hackney`).
3. Excludes any single-word name whose lower-cased form has a Zipf frequency
   of 4.5 or more in the `wordfreq` English list (common words such as
   `Street`, `Sale`, `Hope`, `March`, `Reading`) unless it is listed in
   `scripts/gazetteer_extra.txt` (famous places that are also frequent words:
   `London`, `York`, `Leeds`), then applies `scripts/gazetteer_stoplist.txt`.
   Frequency alone cannot separate a common word from a famous place, so the
   two hand-maintained lists are part of the rule. The script prints the
   names it dropped so they can be reviewed.
4. Writes the sorted, de-duplicated list with a header comment recording the
   GeoNames extract date, the thresholds and the attribution.

`wordfreq` is a dependency of the script only, not of the package. The README
records source, licence (CC BY 4.0), attribution text, refresh date and the
thresholds. The script is reproducible from a given GeoNames dump; the output
is committed.

### OfflineEmailRecognizer

Subclass of Presidio's `EmailRecognizer` whose `validate_result` uses a
module-level `tldextract.TLDExtract(suffix_list_urls=(), cache_dir=None,
fallback_to_snapshot=True)` instead of the package-level `extract`, so the
public suffix list is never fetched.

## Post-processing

Applied in `_postprocess.py` in this order, on the Presidio results for the
whole text:

1. Map entity type to `HitKind`; drop anything not in the table above.
2. Drop results with score below 0.3. Tidy phone, URL and email spans by
   removing an unbalanced leading `(` and trailing `.,;:)` characters that the
   upstream matchers include (`(07700 123456`, `example.org/x.`).
3. Resolve overlaps. Hits are processed in order of start then descending
   length. When two hits overlap:
   - a structured kind beats a model kind, where structured kinds are
     date_of_birth, nhs_number, national_insurance_number, postcode,
     case_reference, email, url, phone, age, date and model kinds are person,
     location, organisation;
   - between two structured kinds, the order just listed wins;
   - otherwise the longer span wins, then the higher score, then the earlier
     member of `HitKind`.
4. Suppress. Compute spans over the text for every whole-word,
   case-insensitive occurrence of each allowlist entry and every match of each
   placeholder pattern. Drop any hit in which every token containing a
   capital letter or a digit lies within one of those spans. A hit whose span
   lies entirely within a suppression span is therefore dropped, and so is a
   model span that merged several placeholders with lowercase joining words
   (`MOTHER2FN MOTHER2SN and FATHER1FN FATHER1SN`), while a hit with an
   uncovered capitalised token (`MOTHER2FN Jones`) is reported. This is
   applied after recognition so a hit is treated the same regardless of
   which recogniser produced it.
5. Sort by start then end and build `Hit` objects.

Allowlist entries are compared after `str.strip()`; empty entries are
ignored. Whole-word means the occurrence is bounded by non-word characters or
the ends of the text.

## Threading and determinism

- One engine per process, built under a lock. All `analyze` calls hold a
  second lock, so concurrent `scan` calls serialise. Callers wanting
  parallelism use processes.
- A test runs eight threads scanning different documents concurrently and
  asserts each result equals the serial result.
- Determinism caveat in the README: identical results are guaranteed for the
  same input, configuration, library versions and CPU architecture. spaCy's
  floating-point inference can differ across architectures.

## Tests

- Unit tests for every recogniser with negative cases: an NHS number with a
  failing check digit, a NINO with a forbidden prefix (`BG`, `GB`, `NK`,
  `KN`, `NT`, `TN`, `ZZ`) or a disallowed letter, a nine-digit phone number,
  a postcode in the allowlist, an outward code without context, a bare year,
  a number over 120 as an age, a non-UK citation.
- Post-processing tests for mapping, threshold, overlap priority and
  suppression, including the containment cases (`Ian Brown` within
  `Dr Ian Brown`; `LOCAL AUTHORITY` within `(LOCAL AUTHORITY)`).
- `redact` tests including the mismatched-text error and overlapping input.
- `scanner_version` and `__version__` tests.
- A no-network test that replaces `socket.socket` and `socket.getaddrinfo`
  with functions that raise, then builds the engine and scans a document
  containing an email address and a URL.
- A thread test as described above.
- Documents tests that build `.docx` and `.xlsx` files in memory with
  python-docx and openpyxl, check text and labels, and check the size and
  zip-bomb rejections and the `ImportError` message without the extra.
- Corpus test: for each `tests/fixtures/corpus/<name>.txt` with
  `<name>.expected.json`, every expected `{kind, text}` entry is present in
  the hits (by kind and exact text, with counts), and no text listed under
  `must_not_report` appears in any hit. The sidecar also carries the
  `allowlist` and `placeholder_patterns` used for that document.
- Corpus contents: at least five synthetic documents written for this
  project, including one anonymised expert witness report with placeholders
  `MOTHER2FN`, `MOTHER2SN`, `FATHER1FN`, `CHILD1FN`, `(LOCAL AUTHORITY)`,
  `(SCHOOL1)`, `(GP SURGERY)`, one leaked town name, one leaked date of
  birth, one leaked NHS number; a clinical letter; a case note with a case
  number and a neutral citation; a plain business letter with no identifiers
  beyond the allowlisted author; a document whose only identifiers are
  placeholders.
- Perf test: generates a document of about 15,000 words, warms the engine,
  scans once and asserts the time is under a budget read from
  `PII_SCANNER_PERF_BUDGET_SECONDS`, default 5. CI sets 10 because hosted
  runners are slower than a laptop. The README records the laptop number.

## Measurement

`scripts/measure.py` loads the corpus, scans each document with its sidecar
configuration, and prints per-kind true positives, false positives, false
negatives, precision and recall, plus totals, the scan time for the perf
document and the resident memory after loading. The README has a table with
these numbers and the date they were taken, and states that the corpus is
synthetic so the figures describe the corpus, not real documents. The numbers
are refreshed whenever the configuration or the corpus changes.

## Delivery

- Tooling from the python-setup skill: uv, ruff (fix, show-fixes, rules B E F
  I UP W, single-line isort), pyright strict over `src` and `tests`, pytest
  with coverage, pre-commit with frozen hooks, Dependabot, `ci.yml` with
  lint, test, build, pip-audit and zizmor jobs, `publish.yml` with trusted
  publishing on release after a tag-matches-version check. Every job that
  needs the model runs `scripts/vendor_model.py` first; the build and
  publish jobs run it before `uv build`.
- Makefile targets: `setup` (model, sync, pre-commit install), `model`,
  `gazetteer`, `check` (ruff, pyright, pytest), `measure`, `bump`
  (`PART=major|minor|patch`, edits `pyproject.toml` and moves the CHANGELOG
  `[Unreleased]` section under the new version and date), `tag` (requires a
  clean tree and a CHANGELOG entry for the version, creates `v<version>`),
  `release` (pushes main and the tag, then `gh release create` with the
  CHANGELOG section as notes, which triggers `publish.yml`).
- `CHANGELOG.md` in Keep a Changelog form. Semantic versioning; the first
  release is 0.1.0.
- `README.md`: what it detects and what it does not; the best-effort caveat;
  the interface; allowlist and placeholder behaviour with the containment

## Out of scope

- Languages other than English.
- PDF or image extraction and OCR.
- Any claim that output is anonymised.
- Per-call model selection or per-call recogniser configuration.
- Parallel scanning within one process.
